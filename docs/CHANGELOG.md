# 更新日志

## v0.4.0 - 2026-11-23

正式发布。发布状态以 GitHub Release 为准。

### 新增

- 插件设置菜单新增「API 格式」下拉选项，保留 Chat Completions（`/chat/completions`）并设为默认值
- 新增 OpenAI Responses API（`/responses`）请求与响应解析，`input_tokens` / `output_tokens` 自动映射到统一统计字段
- 新增「发送 temperature 参数」配置，默认开启；关闭后两种 API 格式均不发送该参数
- 支持手动配置 Anthropic Messages
- 新增 AstrBot、AnySearch、Tavily API 和网页搜索模式，可按配置中心列表顺序依次尝试，并设置超时预算
- 增加统一配置中心、真实用量统计与 AstrBot 已配置模型选择
- 支持为指定游戏提供真实游玩经历，并提供多种写作结构
- 支持使用 AstrBot UMO 统一配置会话白名单，同时保留旧配置兼容模式
- 支持手动关联身份及计数迁移，并在中断或存储故障后恢复迁移；旧会话与管理员配置自动迁移，未能明确映射的限制保留待处理，管理员按连接器与发送者 UID 区分
- 按活动格式输出标题和正文，正文目标 800–1200 字；前置字段按游戏情况补全，缺失时不显示占位符，也不追加额外提示

### 变更与修复

- 活动帖改用官方字段名（游戏当时发售平台 / 玩游戏的时间 / 推荐人群（理由） / 正文），并剔除模型伪造的游戏名、许愿卡等尾注
- 前置信息缺失时按游戏情况生成合理内容：素材里有明确首发平台信息时优先采用，否则按游戏真实平台兜底；素材给出明确发售日期时校验游玩时间不早于该日期，没有发售日期素材时保留模型的合理时期；推荐人群结合游戏特点。不再输出「【请补充……】」，也不再追加「前置信息还差」类尾注，用户写明的内容仍优先保留
- 游玩时间优先采用用户文本中的真实时期（如「初中暑假」「去年冬天」）；用户没给时结合正文故事生成合理时期，素材明确给出年月日时按该日期校验，模型写出的时间不会早于发售
- 写作改为故事优先：有经历时从具体瞬间切入，正文目标 800–1200 字；没有经历时直接生成客观推荐与合理游玩场景，不再另发补充提示
- 管理页搜索页重组为「策略 / 诊断 / 高级参数」，窄屏导航改网格、排序按钮 44px，修改后自动保存，并在页眉与分区提示「已保存 / 草稿预览」、保存进度与失败原因
- 管理页键盘排序后恢复焦点，取消确认弹窗后焦点回到触发按钮；配置冲突时停止自动写入并保留草稿，刷新取得新基线后恢复保存
- 搜索策略收敛为「Astrbot与搜索插件」「搜索API」「网页搜索」三组有序列表：拖动排序、单项开关，按列表从上到下依次尝试并在首个有效结果停止；移除自动/关闭策略行与独立降级开关，旧配置幂等迁移
- 默认改为搜索素材直传（标题/来源/链接/片段，约 3000 字、最多 6 条、单条约 400 字）；AI 汇总降为高级显式选项，旧默认开关幂等迁移
- 网页组改为两路查询（首发平台/玩法机制、体验评价/剧情），共享总超时与结果数，按链接去重并按句子截断片段；两路结果按「查询方向 × 来源」轮转合并，结果上限较小或某轮全重复时也能覆盖两个方向
- 素材预算在写入前逐条校验，长链接不会超预算
- AnySearch 适配真实返回的分节 Markdown（标题 + `- **URL**:` + 摘要），兼容原有 JSON 与 `[标题](链接)`；按结果头/条数判定零结果，区分「确无结果」与「解析失败」并展示本次尝试与跳过原因
- Responses API 明确返回不完整、失败或未完成状态时，不再将部分正文作为成功结果
- 对未知响应状态和错误字段使用安全提示，避免在日志或异常中回显上游原始值
- 调整 AstrBot 搜索能力检查和后端诊断，不再仅凭版本字符串拒绝搜索
- 合并 `build_material_block`／`_truncate_sentences` 的重复实现（此前旧实现覆盖修复版），回归改为导入实际函数并校验 1,000 字预算
- 插件菜单与页面标题改为「小作文生成器」，入口 ID 与路由保持不变

### 工程化

- 新增 Python 3.10 / 3.12 GitHub Actions 持续集成
- 新增核心模块单元测试，覆盖配置、迁移、搜索、成文与浏览器交互
- 重写设计文档，使其与当前白名单、搜索和 AI 调用实现保持一致

## v0.3.4 - 2026-06-12

### 新增

- 插件配置新增「采用搜索结果条数」（1-10，默认3）
- 插件配置新增「是否启用搜索汇总」开关（默认开启，关闭则直接使用原始搜索结果进入生成阶段）
- 插件配置新增「搜索汇文字数限制」（50-500，默认150）

## v0.3.3 - 2026-06-12

### 修复

- 修复搜索汇总逻辑：改为 AI 调用整理搜索结果（不再是正则提取）
- 正确流程：搜索 → AI汇总搜索结果 → AI生成小作文 → 回复文章 → 回复统计
- `ai_client` 新增 `summarize_search()` 方法，专用 Prompt 汇总搜索资料
- `ai_client` 底层重构为 `_call_ai()` 通用方法，支持不同 system prompt 和参数
- 删除 `search_service` 中的 `_build_search_digest` 正则提取逻辑

## v0.3.1 - 2026-06-12

### 变更

- 删除独立的搜索摘要消息，搜索汇总信息整合到统计信息中展示
- 删除插件配置中的「生成后发送搜索信息摘要」开关
- 搜索汇总改为分析整理后的简短摘要，不再直接展示原始搜索片段

## v0.3.0 - 2026-06-12

### 优化

- 搜索服务改为多源并发搜索（Bing + 百度同时搜索），至少从 2 个搜索源获取结果
- 搜索结果自动合并去重，形成搜索信息汇总
- 插件配置新增「生成后发送搜索信息摘要」开关（默认开启），可关闭搜索汇总消息的发送
- 生成后消息顺序：小作文 → 搜索信息摘要（可选）→ 统计信息（可选）
